# 시나리오: 메모 삭제

- **우선순위:** P1 (핵심 CRUD — 되돌릴 수 없는 동작이라 확인 절차와 DB 반영 검증이 중요)
- **대상 URL:** http://localhost:3000
- **데이터 저장소:** Supabase (Server Action 경유)

## 사전 조건

- dev 서버 실행 중, 환경변수 설정됨
- 삭제 대상으로 `E2E 삭제 테스트` 메모를 테스트 시작 시 직접 만든다 (목업 데이터 보호).
- 삭제 확인은 `window.confirm("정말로 이 메모를 삭제하시겠습니까?")`이므로 dialog 핸들러가 필요하다.

## 단계

1. `/` 접속 후 `E2E 삭제 테스트` 카드를 찾고, 현재 "총 N개의 메모" 개수를 기록한다.
2. 카드의 **삭제** 버튼을 클릭한다.
3. confirm 대화상자가 뜨고 문구가 "정말로 이 메모를 삭제하시겠습니까?"인지 확인한 뒤 **수락**한다.

## 기대 결과

- 카드가 목록에서 사라진다.
- 개수가 "총 N-1개의 메모"로 줄어든다.
- 새로고침 후에도 카드가 다시 나타나지 않는다 (DB에서 삭제됨).
- 오류 배너(`data-testid="memo-error"`)가 없다.

## 취소 케이스 (P2)

- confirm 대화상자에서 **취소(dismiss)** → 카드와 개수가 그대로 유지된다.

## 변형 (P2)

- 카드를 클릭해 상세 보기(`memo-viewer`)를 연 뒤 `memo-viewer-delete-btn`으로 삭제 → 뷰어가 닫히고 목록에서 사라진다.
- 이전에 AI 요약을 생성한 메모를 삭제하면 `memo_summaries` 행도 함께 삭제된다 (FK `on delete cascade`).

## 정리

- 수락 케이스에서는 메모가 이미 삭제되므로 별도 정리가 없다. 취소 케이스에서는 만든 메모를 삭제한다.

## 셀렉터 힌트

- 카드 내 삭제 버튼: `card.getByRole('button', { name: '삭제' })`
- 대화상자: `page.once('dialog', d => d.accept())` (취소는 `d.dismiss()`)
