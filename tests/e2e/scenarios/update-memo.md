# 시나리오: 메모 수정

- **우선순위:** P1 (핵심 CRUD — 작성 다음으로 자주 쓰는 기능, 데이터 변경·요약 무효화와 연결)
- **대상 URL:** http://localhost:3000
- **데이터 저장소:** Supabase (Server Action 경유)

## 사전 조건

- dev 서버 실행 중, 환경변수 설정됨
- 수정 대상 메모가 존재한다. 목업 데이터를 건드리지 않도록 테스트 시작 시 `E2E 수정 테스트` 메모를 직접 만들어 사용한다 (제목 `E2E 수정 테스트`, 카테고리 개인, 내용 `수정 전 본문`).

## 단계

1. `/` 접속 후 `E2E 수정 테스트` 카드를 찾는다.
2. 카드의 **편집** 버튼을 클릭한다.
3. "메모 편집" 모달이 열리고, 제목·카테고리·내용·태그가 기존 값으로 채워져 있는지 확인한다.
4. 제목을 `E2E 수정 테스트 (수정됨)`으로 바꾼다.
5. 카테고리를 **학습**으로 바꾼다.
6. 내용을 `수정 후 본문`으로 바꾼다.
7. **수정하기** 버튼을 클릭한다.

## 기대 결과

- 모달이 닫힌다.
- 카드 제목이 `E2E 수정 테스트 (수정됨)`으로, 카테고리 배지가 "학습"으로 바뀐다.
- 목록 개수는 그대로다 (새 메모가 생기지 않음).
- 카드를 열어 상세 보기(`data-testid="memo-viewer"`)를 확인하면 내용이 `수정 후 본문`이고, "수정" 시각이 "작성" 시각보다 이후다.
- 새로고침 후에도 수정 내용이 유지된다.
- 오류 배너(`data-testid="memo-error"`)가 없다.

## 취소 케이스 (P2)

- 편집 모달에서 값을 바꾼 뒤 **취소** → 카드 내용이 변하지 않는다.

## 정리

- `E2E 수정 테스트 (수정됨)` 메모를 삭제한다.

## 셀렉터 힌트

- 카드 내 편집 버튼: `card.getByRole('button', { name: '편집' })`
- 제출 버튼: `getByRole('button', { name: '수정하기' })`
- 상세 보기 편집 버튼: `getByTestId('memo-viewer-edit-btn')`
