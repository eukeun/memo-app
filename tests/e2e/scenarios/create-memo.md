# 시나리오: 메모 작성

- **우선순위:** P0 (핵심 — 앱의 기본 가치. 실패 시 다른 모든 기능이 의미 없음)
- **대상 URL:** http://localhost:3000
- **데이터 저장소:** Supabase (Server Action 경유)

## 사전 조건

- dev 서버 실행 중, `.env.local`에 `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` 설정됨
- 목업 메모 6건이 DB에 존재 (헤더 목록에 "총 6개의 메모" 표시)
- 테스트가 만든 메모는 종료 시 삭제해 DB를 원상태로 되돌린다 (실제 DB 사용)

## 단계

1. `/` 접속 후 메모 카드가 로드될 때까지 대기한다.
2. 헤더의 **새 메모** 버튼을 클릭한다.
3. "새 메모 작성" 모달이 열리는지 확인한다.
4. 제목에 `E2E 작성 테스트`를 입력한다.
5. 카테고리를 **업무**로 선택한다.
6. 내용에 `E2E로 작성한 메모 본문`을 입력한다.
7. 태그 입력란에 `e2e`를 입력하고 Enter를 누른다.
8. **저장하기** 버튼을 클릭한다.

## 기대 결과

- 모달이 닫힌다.
- 목록에 `E2E 작성 테스트` 카드가 나타나고, 카테고리 배지는 "업무", 태그는 `#e2e`로 표시된다.
- 목록 상단 개수가 "총 7개의 메모"로 늘어난다.
- 페이지를 새로고침해도 카드가 유지된다 (DB 영속화 확인).
- 화면 상단에 오류 배너(`data-testid="memo-error"`)가 없다.

## 검증 포인트 (선택)

- 새 행의 `id`가 uuid 형식이다 (Supabase `memos` 조회).

## 부정 케이스 (같은 시나리오의 변형, P1)

- 제목을 비운 채 **저장하기** → 제목 필드의 `required` 브라우저 검증("이 입력란을 작성하세요.")으로 모달이 열린 채 유지되고, 목록 개수는 변하지 않는다.
- 내용을 비운 채 **저장하기** → 내용 필드에는 `required`가 없어서 앱의 `alert("제목과 내용을 모두 입력해주세요.")`가 뜨고, 모달이 열린 채 유지되며 메모는 생성되지 않는다 (dialog 핸들러 필요).

## 정리

- 생성한 `E2E 작성 테스트` 메모를 삭제한다.

## 셀렉터 힌트

- 새 메모 버튼: `getByRole('button', { name: '새 메모' })`
- 제목: `getByRole('textbox', { name: '제목 *' })`
- 카테고리: `getByRole('combobox', { name: '카테고리' })`
- 내용: `getByRole('textbox', { name: '내용 * (마크다운 지원)' })` (`data-testid="memo-content-editor"`)
- 카드: `getByTestId('memo-card')`
